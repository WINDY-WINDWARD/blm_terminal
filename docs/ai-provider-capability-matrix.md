### 2.2 `openai-compatibility` Routing & Zen / Keyless Behavior
1. **Model Prefix Stripping**:
   - Sent: `POST /v1/chat/completions` with body `{"model": "myprefix/test-m1"}`.
   - Upstream received: `POST /v1/chat/completions` with body `{"model": "test-m1"}`.
   - Upstream saw headers: `['Host', 'User-Agent', 'Content-Length', 'Authorization', 'Content-Type', 'Accept-Encoding']`.
2. **`force-model-prefix: true` Enforcement**:
   - Sent: `POST /v1/chat/completions` with body `{"model": "test-m1"}` (unprefixed).
   - CLIProxyAPI rejected request immediately: HTTP 400 `{"error":{"message":"unknown provider for model test-m1","type":"invalid_request_error","code":"model_not_found","param":"model"}}`.
   - Upstream saw **0** requests.
3. **`force-model-prefix: false` Flexibility**:
   - `/v1/models` returned both: `['test-m1', 'myprefix/test-m1']`.
   - Requests with `myprefix/test-m1` and `test-m1` both succeeded (HTTP 200) and arrived upstream with `model: test-m1`.
4. **Keyless & Public Endpoints (OpenCode Zen)**:
   - Config with omitted `api-key-entries` or `api-key-entries: []`: Upstream received **no `Authorization` header** (`auth_header: None`). Request completed with HTTP 200.
   - Config with `api-key-entries: [{api-key: "public"}]`: Upstream received `Authorization: Bearer public`.
   - Config with `api-key-entries: [{api-key: ""}]`: Upstream received no `Authorization` header.
5. **Streaming & Tools**:
   - Streaming request (`stream: true`): Proxy streamed HTTP 200 SSE chunks (`data: {"choices":[{"delta":{"content":"..."}}]}`).
   - Tool call request (`tools: [...]`): Upstream received full tools schema; proxy relayed assistant `tool_calls` structure (`[{"id": "call_123", "type": "function", ...}]`).

### 2.3 `gemini-api-key` Protocol Translation
1. **Config Syntax**:
   - Config with list of strings (`gemini-api-key: ["AIza..."]`) caused immediate process termination (exit code 0).
   - Config with list of objects (`- api-key: "AIza...", base-url: "http://127.0.0.1:<port>", prefix: "gem"`) started successfully.
2. **Endpoint & Body Translation**:
   - Request to proxy: `POST /v1/chat/completions` with model `gem/gemini-2.5-flash` and body `{"messages": [{"role": "user", "content": "Hello Gemini"}]}`.
   - Request received by upstream:
     - Path: `POST /v1beta/models/gemini-2.5-flash:generateContent`
     - Auth: `X-Goog-Api-Key: [REDACTED]`
     - Body: `{"contents":[{"role":"user","parts":[{"text":"Hello Gemini"}]}],"model":"gemini-2.5-flash",...}`
   - Response translation: Upstream Gemini response `{"candidates": [{"content": {"parts": [{"text": "Hello from fake Gemini"}]}}]}` was translated by proxy to standard OpenAI `chat.completion` response `{"choices": [{"message": {"role": "assistant", "content": "Hello from fake Gemini"}}]}`.

### 2.4 `claude-api-key` Protocol Translation & OAuth Disqualification
1. **Config Syntax & Upstream Translation**:
   - Supported fields: `api-key`, `base-url`, `prefix`, `models`, `proxy-url`.
   - Incoming OpenAI request `POST /v1/chat/completions` with model `cld/claude-sonnet-4-5-20250929` arrived upstream at `POST /v1/messages?beta=true`.
   - Upstream received headers: `Authorization: Bearer [REDACTED]`, `Anthropic-Version: 2023-06-01`, `Accept`, `Content-Type`.
   - Incoming native Anthropic request `POST /v1/messages` (with client `x-api-key` and `anthropic-version`) was forwarded upstream to `POST /v1/messages?beta=true` and returned native Anthropic SSE events.
2. **Streaming Upstream Requirement**:
   - Upstream must return an SSE stream. A non-streaming JSON response from upstream causes HTTP 502 with message `claude executor: upstream returned empty stream response`.
3. **`sk-ant-oat` Token Rejection**:
   - When configured with `api-key: "sk-ant-oat01-..."`, CLIProxyAPI detected the token prefix and attempted to fetch Claude OAuth account profile:
     `HTTP 500: {"error":{"message":"populate Claude OAuth account profile: fetch Claude OAuth profile failed with status 401","type":"server_error","code":"internal_server_error"}}`.
   - An `sk-ant-oat` token cannot be used as a static API key in `claude-api-key`.

### 2.5 `stream-bootstrap-timeout` Configuration
- Placement in YAML:
  - Top level (`stream-bootstrap-timeout: 30s`): Ignored by Go parser, has no effect.
  - Under `routing:`: Rejected, process exits code 0.
  - Under `codex:`: **Parsed and accepted** into `CodexConfig.StreamBootstrapTimeoutDuration`.
- Semantics: Determines timeout for initial Codex streaming session connection and event buffer window (`CodexBootstrapBufferableEvent`) before triggering `CodexOverloadBootstrapFailure`.
