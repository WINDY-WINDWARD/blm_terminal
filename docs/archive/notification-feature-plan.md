# Notification Feature — Implementation Plan

> **Status:** Approved
> **Last updated:** 2026-03-21 (rev 3 — fix `__dict__` ORM issue, Next.js dynamic route, date import, dev-gate env var, full test stubs)

---

## Overview

A new `NOTIF` widget for the Tidy Star terminal that surfaces real-time alerts
when stocks in the user's watchlist trigger significant market events. Alerts are
generated by a dedicated background worker in the FastAPI backend and stored in a
new SQLite table. The widget polls the backend every 30 seconds.

---

## User-Facing Behaviour

1. User opens the NOTIF panel via the CommandBar (`/notif` command → focused panel
   becomes `NOTIF`).
2. The NOTIF widget shows a watchlist selector (same list of watchlists available
   in the WatchWidget), defaulting to the user's currently active watchlist.
   **The NOTIF widget's selector does NOT write back to `activeWatchlistIdAtom`.**
   It uses a local `useState` so switching watchlists in NOTIF has no side effects
   on other panels.
3. Notifications are shown newest-first, grouped under tabs by type.
4. Clicking any notification row sets the global active symbol to that stock
   (`activeSymbolAtom` + `activeExchangeAtom`), switching the CHART/WATCH/etc.
   panels to that symbol.
5. Each notification has a dismiss (×) button. Dismissed notifications are
   soft-deleted (`is_read = True`) — not permanently removed.
6. A "Clear All" button in the header dismisses every unread notification for the
   selected watchlist.

---

## Trigger Conditions

The background worker checks watchlist symbols against these data sources:

| Trigger Type | Source | Condition | Message Template |
|---|---|---|---|
| `52w_high_breakout` | NSE 52-week High | Symbol present in NSE 52-week high list | `{SYMBOL} hit a new 52-week HIGH @ ₹{price}` |
| `52w_low_breakout` | NSE 52-week Low | Symbol present in NSE 52-week low list | `{SYMBOL} hit a new 52-week LOW @ ₹{price}` |
| `volume_breakout` | NSE Volume Gainers | Symbol present in NSE volume gainers list | `{SYMBOL} showing volume breakout ({ratio}x avg)` |
| `top_gainer` | NSE Top Gainers | Symbol present in NSE top gainers | `{SYMBOL} among TOP GAINERS ({pChange}%)` |
| `top_loser` | NSE Top Losers | Symbol present in NSE top losers | `{SYMBOL} among TOP LOSERS ({pChange}%)` |
| `bulk_deal` | NSE Bulk Deals | Symbol appears in NSE bulk deals within last 7 days | `{SYMBOL} — BULK deal: {qty:,} shares @ ₹{watp}` |
| `block_deal` | NSE Block Deals | Symbol appears in NSE block deals within last 7 days | `{SYMBOL} — BLOCK deal: {qty:,} shares @ ₹{watp}` |
| `insider_buy` | screener.in Insider Trades | Symbol appears in screener.in insider BUY within last 7 days | `{SYMBOL} insider BUY: {acquirer_name} acquired {qty:,} shares` |
| `insider_sell` | screener.in Insider Trades | Symbol appears in screener.in insider SELL within last 7 days | `{SYMBOL} insider SELL: {acquirer_name} sold {qty:,} shares` |

## Deduplication Strategy

### Bug in rev 1 (fixed)

The original plan used `UniqueConstraint(watchlist_id, symbol, trigger_type, triggered_at)`.
Since `triggered_at` is a full timestamp (`YYYY-MM-DD HH:MM:SS`), two inserts for the
same symbol+type on the same day but different 5-minute cycles would not conflict —
causing notification spam. The fix: **use a date-only window key**.

### Fix: Two-column approach

The `notifications` table has two date columns:

```python
triggered_at: Mapped[datetime] = mapped_column(DateTime, ...)
triggered_date: Mapped[date]     = mapped_column(Date, ...)  # date-only, no time
```

The `UniqueConstraint` uses `triggered_date` (not `triggered_at`):

```python
UniqueConstraint(
    "watchlist_id", "symbol", "trigger_type", "triggered_date",
    name="uq_notification_daily",
)
```

In the worker, `triggered_date` is always set explicitly to `datetime.now().date()` —
never relying on the DB server clock. This ensures one insert per (watchlist, symbol,
type, date) tuple per day, regardless of how many cycles run.

### Per-cycle seen set

The worker also maintains an in-memory `seen_today` set as a pre-flight check,
populated by a single DB query at the start of each cycle:

```python
seen_today: set[tuple[int, str, str]] = {
    (wl_id, symbol, trigger_type)
    for (wl_id, symbol, trigger_type) in existing_unread_rows
}
```

This avoids unnecessary DB insert attempts for symbols already notified this cycle,
though the `UniqueConstraint` would catch them anyway.

## Worker Scheduling

### Two-mode operation

The worker runs in one of two modes based on whether the market is open:

| Mode | When | Interval | Checks |
|---|---|---|---|
| **Full cycle** | Market open (Mon–Fri 09:15–15:30 IST) | 5 min | All 9 trigger types |
| **Reduced cycle** | Market closed | 30 min | Deals + Insider trades only |

Rationale: bulk/block deals and insider trades are filed after market hours and
remain relevant overnight. 52W breakouts, volume gainers, and top movers are
intraday phenomena — skipping them outside hours avoids unnecessary NSE calls.

```python
def _watchlist_notification_worker() -> None:
    while not _shutdown_event.is_set():
        if _is_market_open():
            _notification_cycle_full()
            _sleep_interruptible(NOTIFICATION_CHECK_INTERVAL)  # 5 min
        else:
            _notification_cycle_reduced()  # deals + insider only
            _sleep_interruptible(AFTER_HOURS_INTERVAL)        # 30 min
```

### Per-cycle workflow (full mode)

1. Query all `WatchlistItem` rows grouped by `watchlist_id`
2. Query existing unread notifications for today → build `seen_today` set
3. Fetch market snapshots via cached NSE client methods:
   - `get_52week_high()`, `get_52week_low()`
   - `get_volume_gainers()`
   - `get_top_gainers()`, `get_top_losers()`
   - `get_largedeal_snapshot()`
4. For each watchlist symbol:
   - Check membership in each snapshot
   - If symbol triggers and `(wl_id, symbol, trigger_type)` not in `seen_today`:
     → build notification row, add to batch
5. Upsert all rows via `sqlite_insert().on_conflict_do_nothing()`
6. Run cleanup (read notifications > 30 days old)
7. Sleep

### Insider trade handling

Insider trades are fetched per-symbol from `screener_client.get_insider_trades()`.
A per-cycle cache (dict keyed by symbol) prevents redundant fetches within the
same cycle. The cache is not persisted between cycles — screener.in is checked
fresh each cycle, which is appropriate since new filings can appear at any time.

Filter: `transaction_date >= (today - 7 days)`

#### 1. `backend/app/models/notification.py`

```python
"""SQLAlchemy ORM model for watchlist stock notifications."""

from datetime import date, datetime

from sqlalchemy import (
    Boolean,
    Date,
    DateTime,
    ForeignKey,
    Index,
    Integer,
    String,
    UniqueConstraint,
    func,
)
from sqlalchemy.orm import Mapped, mapped_column

from app.database import Base


class Notification(Base):
    """Persisted notification for a watchlist stock triggering a market event."""

    __tablename__ = "notifications"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    watchlist_id: Mapped[int] = mapped_column(
        ForeignKey("watchlists.id", ondelete="CASCADE"), nullable=False
    )
    symbol: Mapped[str] = mapped_column(String(32), nullable=False)
    exchange: Mapped[str] = mapped_column(String(16), default="NSE")
    trigger_type: Mapped[str] = mapped_column(String(32), nullable=False)
    message: Mapped[str] = mapped_column(String(256), nullable=False)
    triggered_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=False), nullable=False
    )
    triggered_date: Mapped[date] = mapped_column(Date, nullable=False)
    is_read: Mapped[bool] = mapped_column(Boolean, default=False, nullable=False)

    __table_args__ = (
        UniqueConstraint(
            "watchlist_id",
            "symbol",
            "trigger_type",
            "triggered_date",
            name="uq_notification_daily",
        ),
        Index("ix_notifications_watchlist_unread", "watchlist_id", "is_read"),
        Index("ix_notifications_triggered_date", "triggered_date"),
    )
```

**Key design decisions:**
- `triggered_at` is set explicitly by the worker (`datetime.now()`) — no
  `server_default=func.now()` because the application must control the date value
  for deduplication to work correctly.
- `triggered_date` is the date-only counterpart used in the `UniqueConstraint`.
  Both columns are always set together to the same datetime/date pair.
- `ondelete="CASCADE"` on `watchlist_id` — deleting a watchlist removes all its
  notifications.
- `Index("ix_notifications_triggered_date")` speeds up the cleanup query.

**GET implementation:**

```python
@router.get("/notifications", response_model=list[NotificationOut], tags=["notifications"])
async def list_notifications(
    watchlist_id: int = Query(default=1),
    db: AsyncSession = Depends(get_db),
) -> list[NotificationOut]:
    stmt = (
        select(Notification)
        .where(Notification.watchlist_id == watchlist_id, Notification.is_read == False)
        .order_by(Notification.triggered_at.desc())
    )
    res = await db.execute(stmt)
    return [NotificationOut.model_validate(n) for n in res.scalars().all()]
```

**DELETE single — must verify watchlist ownership:**

```python
@router.delete("/notifications/{notif_id}", tags=["notifications"])
async def dismiss_notification(
    notif_id: int,
    watchlist_id: int = Query(...),
    db: AsyncSession = Depends(get_db),
) -> dict:
    notif = await db.get(Notification, notif_id)
    if notif is None:
        raise HTTPException(status_code=404, detail=f"Notification {notif_id} not found")
    if notif.watchlist_id != watchlist_id:
        raise HTTPException(
            status_code=403,
            detail=f"Notification {notif_id} does not belong to watchlist {watchlist_id}",
        )
    notif.is_read = True
    await db.commit()
    return {"ok": True}
```

> **Security note:** The `watchlist_id` guard on DELETE is mandatory. Without it, a
> user could soft-delete another watchlist's notifications by guessing sequential IDs.

**`_notification_cycle_full()`** — all 9 trigger types:

```python
def _notification_cycle_full() -> None:
    """Full cycle: 52W, Volume, Gainers/Losers, Deals, Insider. Called in worker thread."""
    try:
        logger.info("notification_cycle_full: starting")
        now = datetime.now()
        today_date = now.date()

        # 1. Fetch watchlist symbols
        symbols_by_watchlist = _get_watchlist_symbols()
        if not symbols_by_watchlist:
            logger.debug("notification_cycle_full: watchlist is empty, skipping")
            return

        # 2. Build seen_today set from existing unread notifications
        seen_today = _get_seen_today()
        pending: list[Notification] = []

        # 3. Fetch market snapshots (all cached)
        high52 = {r.symbol for r in _nse_client.get_52week_high().itertuples()}
        low52  = {r.symbol for r in _nse_client.get_52week_low().itertuples()}
        vol    = {r.symbol for r in _nse_client.get_volume_gainers().itertuples()}
        gainers = {r.symbol for r in _nse_client.get_top_gainers().itertuples()}
        losers  = {r.symbol for r in _nse_client.get_top_losers().itertuples()}
        deals   = _nse_client.get_largedeal_snapshot()

        # 4. Insider trade cache for this cycle
        insider_cache: dict[str, list[dict]] = {}

        # 5. Process each watchlist
        for wl_id, symbols in symbols_by_watchlist.items():
            for symbol in symbols:
                alerts = []

                # 52W / Volume / Movers
                if symbol in high52:
                    price = _get_symbol_price(symbol, high52)
                    alerts.append(("52w_high_breakout",
                                   f"{symbol} hit a new 52-week HIGH @ ₹{price}"))
                if symbol in low52:
                    price = _get_symbol_price(symbol, low52)
                    alerts.append(("52w_low_breakout",
                                   f"{symbol} hit a new 52-week LOW @ ₹{price}"))
                if symbol in vol:
                    ratio = _get_volume_ratio(symbol, vol)
                    alerts.append(("volume_breakout",
                                   f"{symbol} showing volume breakout ({ratio}x avg)"))
                if symbol in gainers:
                    pchg = _get_pchange(symbol, gainers)
                    alerts.append(("top_gainer",
                                   f"{symbol} among TOP GAINERS ({pchg:+.1f}%)"))
                if symbol in losers:
                    pchg = _get_pchange(symbol, losers)
                    alerts.append(("top_loser",
                                   f"{symbol} among TOP LOSERS ({pchg:+.1f}%)"))

                # Deals (filtered to last 7 days)
                for deal in deals.get_deals_for_symbol(symbol):
                    if deal.is_recent(days=7):
                        alerts.append((f"{deal.type}_deal",
                                       f"{symbol} — {deal.type} deal: "
                                       f"{deal.qty:,} shares @ ₹{deal.watp}"))

                # Insider trades (cached)
                if symbol not in insider_cache:
                    insider_cache[symbol] = _fetch_insider_trades_cached(symbol)
                for trade in insider_cache[symbol]:
                    if trade.is_recent(days=7):
                        direction = trade.buy_sell.lower()
                        if direction in ("buy", "acquisition"):
                            t = "insider_buy"
                        else:
                            t = "insider_sell"
                        alerts.append((t,
                                       f"{symbol} insider {direction.upper()}: "
                                       f"{trade.acquirer_name} {direction} "
                                       f"{trade.qty:,} shares"))

                # 6. Upsert alerts not yet seen today (plain dicts — not ORM objects)
                for trigger_type, message in alerts:
                    key = (wl_id, symbol, trigger_type)
                    if key in seen_today:
                        continue
                    seen_today.add(key)
                    pending.append({
                        "watchlist_id": wl_id,
                        "symbol": symbol,
                        "exchange": "NSE",
                        "trigger_type": trigger_type,
                        "message": message,
                        "triggered_at": now,
                        "triggered_date": today_date,
                        "is_read": False,
                    })

        # 7. Bulk upsert
        if pending:
            _bulk_upsert_notifications(pending)

        logger.info("notification_cycle_full: %d notifications upserted", len(pending))
    except Exception:
        logger.exception("notification_cycle_full: unhandled exception")
```

**`_notification_cycle_reduced()`** — deals + insider only (outside market hours):
Identical logic but skips the NSE snapshot fetches (52W, Volume, Gainers/Losers) and
only iterates over deal + insider trade checks. Runs every 30 minutes.

**`_bulk_upsert_notifications()`:**

```python
def _bulk_upsert_notifications(rows: list[dict]) -> None:
    """rows is a list of plain dicts — never ORM objects.
    
    Passing SQLAlchemy ORM instances directly to sqlite_insert().values()
    via r.__dict__ would include SQLAlchemy's internal _sa_instance_state key,
    causing the insert to fail or behave unexpectedly. Dicts are used instead.
    """
    from sqlalchemy.dialects.sqlite import insert as sqlite_insert
    with _SyncSessionLocal() as session:
        stmt = (
            sqlite_insert(Notification)
            .values(rows)
            .on_conflict_do_nothing(constraint="uq_notification_daily")
        )
        session.execute(stmt)
        session.commit()
```

> Uses `sqlite_insert().on_conflict_do_nothing()` — not `session.add_all()`.
> `add_all` raises on constraint violation; upsert silently skips duplicates.
> The DB-level constraint is the authoritative dedup mechanism.
> Dicts are built in the caller from the notification data; the ORM model is
> never instantiated in the batch path.

**`_get_seen_today()`:**

```python
def _get_seen_today() -> set[tuple[int, str, str]]:
    today = datetime.now().date()
    with _SyncSessionLocal() as session:
        rows = session.execute(
            select(Notification.watchlist_id,
                   Notification.symbol,
                   Notification.trigger_type)
            .where(Notification.triggered_date == today,
                   Notification.is_read == False)
        )
        return {(r[0], r[1], r[2]) for r in rows}
```

**Cleanup (once per day):**

```python
_cleanup_last_run: datetime | None = None

def _run_cleanup_if_due() -> None:
    global _cleanup_last_run
    now = datetime.now()
    if _cleanup_last_run is not None and (now - _cleanup_last_run).total_seconds() < CLEANUP_INTERVAL:
        return
    cutoff = datetime.combine(now.date() - timedelta(days=CLEANUP_READ_AFTER_DAYS),
                               datetime.min.time())
    with _SyncSessionLocal() as session:
        deleted = session.execute(
            delete(Notification).where(
                Notification.is_read == True,
                Notification.triggered_at < cutoff,
            )
        )
        session.commit()
        logger.info("notification_cleanup: deleted %d read notifications older than %s",
                    deleted.rowcount, cutoff.date())
    _cleanup_last_run = now
```

> Cleanup runs at most once per 24 hours (not every 5-min cycle) — more efficient
> and sufficient for a 30-day retention window.

class TestNotificationsDedup:
    """Dedup is enforced by the UniqueConstraint — these tests verify it."""

    def test_dedup_same_watchlist_same_day_inserted_once(self, test_db, require_dev_env):
        """Two inserts for the same (watchlist, symbol, trigger_type, date)
        should result in only one row — the second is silently ignored.
        """
        from app.models.notification import Notification

        # Ensure the symbol is in the watchlist
        requests.post(f"{BASE}/api/watchlist",
                      json={"symbol": TEST_SYMBOL, "exchange": "NSE"})

        # Manually seed the first notification
        row1 = Notification(
            watchlist_id=TEST_WATCHLIST_ID,
            symbol=TEST_SYMBOL,
            exchange="NSE",
            trigger_type="bulk_deal",
            message=f"{TEST_SYMBOL} — BULK deal: 100 shares",
            triggered_at=datetime.now(),
            triggered_date=date.today(),
            is_read=False,
        )
        test_db.add(row1)
        test_db.commit()
        test_db.refresh(row1)
        row1_id = row1.id

        # Trigger the worker (it will try to insert the same notification)
        requests.post(f"{BASE}/api/notifications/trigger")

        # Count rows for this (watchlist, symbol, type, date)
        from sqlalchemy import select, func
        count = test_db.execute(
            select(func.count()).select_from(Notification).where(
                Notification.watchlist_id == TEST_WATCHLIST_ID,
                Notification.symbol == TEST_SYMBOL,
                Notification.trigger_type == "bulk_deal",
                Notification.triggered_date == date.today(),
            )
        ).scalar_one()

        assert count == 1, (
            f"Expected exactly 1 notification for {TEST_SYMBOL}/bulk_deal/today, "
            f"got {count}. The UniqueConstraint may not be enforcing deduplication."
        )

        # Clean up
        test_db.delete(test_db.get(Notification, row1_id))
        test_db.commit()

    def test_dedup_next_day_is_allowed(self, test_db, require_dev_env):

## Data Flow — Notification Lifecycle

```
1. Worker wakes (every 5 min during market hours, every 30 min after hours)
        │
        ▼
2. Query watchlist items + existing unread notifications today
        │
        ▼
3. Build seen_today set: {(wl_id, symbol, trigger_type)}
        │
        ▼
4. Fetch market snapshots (NSE client, all cached)
        │
        ▼
5. For each watchlist symbol:
   - Check each data source
   - If symbol triggers AND key not in seen_today:
       → add to pending batch
       → add key to seen_today
        │
        ▼
6. Bulk upsert pending rows via sqlite_insert().on_conflict_do_nothing()
   → DB constraint silently ignores any remaining duplicates
        │
        ▼
7. Cleanup: hard-delete read notifications > 30 days old (once/day)
        │
        ▼
8. User's NOTIF widget polls /api/notifications?watchlist_id=N
        │
        ▼
9. Widget renders notifications (newest first, tab-filtered)
        │
        ▼
10. User clicks notification
        │
        ▼
11. setActiveSymbolAtom + setActiveExchangeAtom
    → CHART/WATCH panels switch to that stock
        │
        ▼
12. User dismisses (×) or "Clear All"
        │
        ▼
13. DELETE /api/notifications/{id}?watchlist_id=N
    → API verifies watchlist_id ownership → 403 if mismatch
    → Sets is_read = True
        │
        ▼
14. queryClient.invalidateQueries → widget refetches → notification gone
```

## Error Handling

### Backend Worker
- All NSE calls wrapped in try/except; one bad symbol does not abort others.
- Screener failures logged and skipped for that cycle.
- DB upsert failures (constraint violations) logged and silently ignored.
- **Never let exceptions propagate out of the worker loop.**

### API Router
- `DELETE /api/notifications/{id}`: 403 if `watchlist_id` does not match.
- `DELETE /api/notifications?all=true`: 400 if `all=true` is missing.
- Standard `HTTPException` with `{"detail": "..."}` JSON responses.
- Next.js proxy returns `{error: string}` with 502 on backend unreachable.

### Frontend Widget
- Loading: amber pulsing "LOADING NOTIFICATIONS..."
- Error: red "Fetch Failed" + error message + retry button
- Empty: "No new alerts for {watchlistName}." with watchlist name displayed
- Mutation errors: logged to console (toast optional v2)

## Performance Considerations

1. **NSE snapshots cached** — TTLCache-backed NSE client. Worker calls hit cache
   on every cycle except first of the TTL window.
2. **Insider trade per-cycle cache** — one fetch per symbol per worker cycle.
   Reduced cycle (30 min outside hours) further limits screener calls.
3. **seen_today set** — single DB query per cycle instead of N lookups per symbol.
4. **Bulk upsert** — all pending rows inserted in one `session.execute()` call.
   `on_conflict_do_nothing` means the DB handles deduplication without app-side
   exception handling overhead.
5. **Indexed queries** — `ix_notifications_watchlist_unread` covers the GET query
   (filter + sort). `ix_notifications_triggered_date` covers cleanup.
6. **Widget polling** — 30-second interval. Appropriate for intraday alerts.
7. **Cleanup throttled** — once per 24 hours, not every cycle.
