# Desktop Conversion Context

## Architectural Decisions & Constraints

- **No Next.js Standalone Export**: `output: "standalone"` cannot be used because it generates a generic server that ignores the custom `server.js` housing the critical `/ws/market` in-process handler. We must package the raw `.next` output and run the custom `server.js` directly via Electron's Node.js runtime.
- **OS-Safe Paths for PyInstaller**: The Python backend natively writes logs to `Path(__file__).parent / "logs"` and uses `./data.db`. Inside a compiled PyInstaller `.exe`, this resolves to an ephemeral `_MEIPASS` directory or read-only `Program Files`. We must use OS-safe paths (e.g., `%APPDATA%`) injected via environment variables (`LOG_DIR`, `DB_PATH`) to prevent crashes or data loss. *Note: In `isDev` mode, Electron now intentionally points `DB_PATH` back to the repository's `backend/data.db` to preserve the developer's existing 1.3GB database during testing.*
- **Jotai SessionStorage Limitations**: Popped-out widgets open in new OS windows, which do not inherit `sessionStorage` (used heavily via `tabStorage` for isolated layouts). To maintain context (like active watchlist), the pop-out button must serialize this state into URL query parameters to rehydrate the Jotai store on mount.
- **Native Dependencies (`sharp`)**: Next.js image optimization relies on `sharp`. Native `.node` binaries cannot execute within an Electron `.asar` wrapper. We must explicitly unpack them using `asarUnpack`.
- **MCP Hook Deprecation**: Bundling the FastAPI backend in PyInstaller effectively hides its standard I/O streams from external processes (like Claude Desktop). Implementing a bypass just for MCP adds unnecessary complexity to the Electron desktop bundle, so we opted to deprecate `run_mcp_stdio.py`.

## New Decisions (Code Review & AI Configuration)

- **AI Chat Stream Timeout**: The Next.js catch-all proxy (`route.ts`) aggressively applied a 15-second default timeout to all requests. We must ensure `AiWidget.tsx` explicitly passes `Accept: text/event-stream` and remove/extend the hard abort timeout for streams so long-reasoning models (like Minimax M2.7) are not abruptly cut off.
- **Dynamic AI Model Polling**: To avoid hardcoding third-party model limits, the frontend will query the FastAPI backend (which will query the Zen/Go `/v1/models` endpoint) to fetch available models in real-time, including free models. Gemini models remain hardcoded as they are tied to specific Google Cloud project scopes.
- **FastAPI Gemini OAuth (ag_login.py)**: The `ag_login.py` script was a CLI tool that span up a temporary web server to catch Google OAuth callbacks. In a compiled desktop application, running standalone CLI scripts is jarring. We are migrating this OAuth flow directly into the FastAPI backend so it is seamlessly triggered from the Settings UI and autonomously maintained.
- **Database-Driven Credentials**: All AI credentials (`ai_provider`, `ai_api_key`) must be migrated from `.env` to the SQLite `system_config` table so users can edit them via the UI without modifying system files. Background workers (like `ai_summarizer.py`) must be updated to read dynamically from SQLite.

## New Decisions (AI Chat Document Uploads)

- **Library + sessions, not session-owned files**: documents live in a per-user library joined to sessions through `chat_document_sessions` (many-to-many). Uploading does not create a chat session; the frontend stages `document_id`s and the first `/ai/chat` call creates the session and attaches them. This is what makes uploads-before-first-message, session deletion (detach only) and re-attaching a document to a different chat all work.
- **Raw FTS5 DDL inside the migration**: `pdf_pages_fts` is created with `CREATE VIRTUAL TABLE ... USING fts5(...)` via `op.execute`. Alembic's `op.create_table` cannot emit a virtual table, and `Base.metadata.create_all()` cannot express one either, so the migration is the only place this can live.
- **Read-only SQL scoped to one document**: CSV uploads are materialised as one SQLite table per document (`csv_doc_<id>`). `query_csv` opens a dedicated connection with `PRAGMA query_only=ON` plus a `sqlite3` authorizer that permits `SELECT`/`FUNCTION` and `READ` only on that document's table — writes, `PRAGMA`, `ATTACH`, multi-statement strings and cross-table reads are all rejected (proved in `tests/test_document_service.py`).
- **Ownership comes from the session, never from the model**: `run_chat_agent` takes the authenticated `user_id` and injects it into every document tool call at dispatch time; the tool schemas deliberately do not expose `user_id` to the model.
- **Binary-safe proxy**: the catch-all proxy reads multipart bodies with `request.arrayBuffer()`. The previous `request.text()` path decoded PDF bytes as UTF-8 with replacement characters, corrupting uploads before FastAPI ever saw them.
- **PyInstaller lazy-import bundling**: both build scripts collect `pypdf` and add `python_multipart` as a hidden import. PyInstaller cannot see the lazily imported `pypdf`, and the upload route is the first `File(...)` parameter in the backend, which makes `python_multipart` required at route-definition time. `backend/blm-backend.spec` is a generated PyInstaller by-product (gitignored) and is NOT the build input — `scripts/build_backend.ps1` / `.sh` are.
- **OCR out of scope but detected**: scanned PDFs are flagged via a text-density heuristic and the model is told the file has no extractable text layer instead of silently receiving empty pages.
