# Desktop Conversion Context

## Architectural Decisions & Constraints

- **No Next.js Standalone Export**: `output: "standalone"` cannot be used because it generates a generic server that ignores the custom `server.js` housing the critical `/ws/market` in-process handler. We must package the raw `.next` output and run the custom `server.js` directly via Electron's Node.js runtime.
- **OS-Safe Paths for PyInstaller**: The Python backend natively writes logs to `Path(__file__).parent / "logs"`. Inside a compiled PyInstaller `.exe`, this resolves to an ephemeral `_MEIPASS` directory. We must use OS-safe paths (e.g., `%APPDATA%`) injected via environment variables (`LOG_DIR`, `DB_PATH`) to prevent crashes or data loss.
- **Jotai SessionStorage Limitations**: Popped-out widgets open in new OS windows, which do not inherit `sessionStorage` (used heavily via `tabStorage` for isolated layouts). To maintain context (like active watchlist), the pop-out button must serialize this state into URL query parameters to rehydrate the Jotai store on mount.
- **Native Dependencies (`sharp`)**: Next.js image optimization relies on `sharp`. Native `.node` binaries cannot execute within an Electron `.asar` wrapper. We must explicitly unpack them using `asarUnpack`.
- **MCP Hook Deprecation**: Bundling the FastAPI backend in PyInstaller effectively hides its standard I/O streams from external processes (like Claude Desktop). Implementing a bypass just for MCP adds unnecessary complexity to the Electron desktop bundle, so we opted to deprecate `run_mcp_stdio.py`.
- **GlobalAppProviders Extraction**: In multi-window desktop environments, popped-out widget windows have their own DOM document and component tree. If WebSocket connections (`marketDataService.connect()`) or OpenAlgo health checks are inside `TerminalContainer`, popped-out widgets running standalone in `/widget/[widgetType]` would lack live feeds and backend status. Moving connection lifecycles to `<GlobalAppProviders>` inside root `Providers` ensures all windows automatically inherit full connectivity.
- **Isolated Widget Page Route**: `src/app/widget/[widgetType]/page.tsx` renders a single widget filling 100vw/100vh with no command bar, terminal panels, or grid system. It deserializes any state provided in search parameters (such as `watchlistId`, `symbol`, `category`) directly into the corresponding Jotai atoms on mount, then renders the widget seamlessly wrapped in an `ErrorBoundary`.
- **Pop-out Button & State Serialization**: In `Panel.tsx`, a pop-out button is rendered in the panel header. When clicked, it builds `/widget/${title}?symbol=${activeSymbol}&watchlistId=${activeWatchlistId}&category=${moversCategory}` and calls `window.open(url, '_blank', 'width=1000,height=700')`. In a browser, this opens a popup window; in Electron, `webContents.setWindowOpenHandler` will intercept this and instantiate a native desktop `BrowserWindow`.
- **Runtime API Key Storage in SQLite System Config**: To liberate users from requiring a `.env` file packaged inside a desktop binary, API keys (`openalgo.url`, `openalgo.api_key`, `ai.api_key`, `ai.opencode_zen_api_key`) can be configured via UI in SettingsWidget and stored persistently in `system_config`. Next.js proxy routes query `/api/system-config` or check environment variables as fallbacks.
- **Deprecating MCP Integration**: PyInstaller single-file executables run in an isolated bundle. Attempting to support Claude Desktop MCP stdio redirects inside an Electron app bundle is fragile and unneeded for a self-contained financial desktop client.
- **OS-Safe Paths for Logs and Database**: Reading `os.getenv("LOG_DIR")` and `os.getenv("DB_PATH")` enables Electron to specify persistent directories (such as `%APPDATA%/blm-terminal/logs` and `%APPDATA%/blm-terminal/data.db`) across desktop updates without touching binary files.
- **PyInstaller Bundling**: We bundle `backend/main.py` using `--onefile` into `dist-backend/blm-backend.exe`, packaging Alembic migrations and config via `--add-data "backend/alembic;alembic"` (on Windows) and hidden imports for `aiosqlite`, `rookiepy`, `sqlalchemy.dialects.sqlite`, and `uvicorn.logging`.
- **Electron Multi-Window & Process Orchestration**: `electron/main.js` acquires dynamic ports using `get-port` for both Next.js and Python. It spawns Next.js's custom `server.js` using Node `child_process.fork()` and Python's `blm-backend.exe` (or fallback `python main.py` in dev) via `child_process.spawn()`. All popup windows created via `window.open` are captured by `webContents.setWindowOpenHandler` and spawned as frameless or title-controlled `BrowserWindow` instances sharing session partition. Process killing is registered on `app.on('before-quit')` and `app.on('quit')` using tree-kill logic.
- **Release Versioning System (`YYYY.M.B`)**: `electron-builder`, `npm`, and semantic versioning parsers forbid leading zeros (e.g. `2026.09.1` fails validation; `2026.9.1` complies). Using `YYYY.M.B` (e.g., Year 2026, Month 9, Build 1) guarantees strict SemVer compatibility while satisfying the requested calendar-and-build versioning format.
- **Auto-Updates via GitHub Releases**: `electron-updater` handles background checks, progressive downloads, and notification-driven app restarts powered by `latest.yml` manifests generated by `electron-builder` in GitHub Actions.
- **Network Resilience & Timeouts**: Frontend auth checks and server proxies now have explicit `AbortSignal.timeout` protections so network lag or downstream backend issues never permanently freeze the UI.
